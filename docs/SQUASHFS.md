# SquashFS development

The SquashFS reader, introduced in 0.5.0, provides **BIDS Explorer: Inspect SquashFS Image** in the Command Palette and native Explorer. It reads the 96-byte SquashFS 4.0 superblock on the workspace host. The report includes image size, inode count, compression and block size. Inodes include files and directories, and are not a count of BIDS participants. The inspection uses no external tool and publishes no member coverage. [Upstream superblock definition](https://github.com/plougher/squashfs-tools/blob/master/squashfs-tools/squashfs_fs.h)

A bounded Rorqual probe sampled 12 published UKB images. The largest sampled image was 11.89 TB, and the highest sampled inode count was 608,580. The installed `unsquashfs` 4.4-git.1 advertises recursive listing but has neither a depth limit nor a member-to-stdout option in its help output. Newer tools advertise depth limits. Capability detection belongs on the workspace host. [Upstream unsquashfs usage](https://github.com/plougher/squashfs-tools/blob/master/Documentation/4.7.4/USAGE-UNSQUASHFS.md)

**Browse SquashFS Image** opens one image in a paged picker. The reader follows the directory metadata directly, with up to 200 immediate entries per page in the picker and 96 metadata blocks per request. Choose a directory to descend or **Next page** to continue. Continuations carry their position in the current directory and are valid only for the same image revision. The reader supports uncompressed metadata blocks and gzip-compressed metadata blocks. File payloads, symlink targets, and descendants of unopened directories are outside each page read. The picker is per image.

In the logical BIDS tree, add the collection directory containing the shards. The tree merges up to 64 contributing SquashFS streams per branch, in batches of four, and emits up to 200 logical names per page. Use Previous page and Next page to move through the listing. Recent page checkpoints are bounded, and navigating further back can replay earlier pages. The merge reads directory metadata on the workspace host, keeps physical image and member paths for each choice, and can look through a single wrapper that contains BIDS entries. If a shard cannot be listed, the tree reports partial coverage. If an image changes between pages, refresh the branch. A branch whose names cannot be merged in logical order reports an error. Selecting a regular member reads its inode and data blocks by position. UTF-8 text previews are limited to 1 MiB. NIfTI members up to 512 MiB use the private archive image cache and the built-in viewer by default; **Open Image With** offers external editors. Data and fragments can be uncompressed or gzip compressed. Selecting a bval or bvec opens the gradient visualization when the same-stem pair is present in the same shard directory. TSV previews also look for their same-directory JSON dictionary.

## Historical reader measurements

The compiled inspector was also run directly on Rorqual against three of those images. Header checks took roughly 31–43 ms per image in that run, including filesystem attribute checks. It identified xz on the small image and the gzip codec with uncompressed metadata and data flags on both large images. The results cover fixed-size reads on the host. That header probe did not measure SSH transfer latency or member opening; later member/viewer checks are recorded in [0.5.0 validation](MILESTONE_0.5.0.md) and [Compatibility](COMPATIBILITY.md).

A separate host probe followed the single top-level directory in each of the two large sampled shards and read two consecutive 200-entry pages per shard. The pages contained no repeated names. First child pages took 2–7 ms and continuation pages took 2–48 ms in this single run. These are host measurements with uncontrolled filesystem cache state. The probe reported counts only and did not open file payloads.

The compiled logical reader ran twice on Rorqual against the published UKB collection. Twelve of 13 images contributed; one uses compressed directory metadata the reader cannot decode. The first three pages had 228, 200 and 200 visible rows with no repeated source identities between pages. The first page includes duplicate file choices, so the row count can exceed the 200-name budget. The three host-side page reads took 38/40/41 ms on the first run and 39/15/11 ms on the repeat. One participant merged across 12 images and expanded to two sessions; the expansion took 56.5 seconds on the first run and 2 ms on the repeat. Filesystem cache state was uncontrolled. These measurements exclude VS Code rendering and SSH transport and do not include member payload reads.

Repeated README, JSON and TSV members at the same logical path share an expandable row. The children open the individual shard versions. Select the grouped dataset description or use its inline open action to compare recorded field values and their sources. The comparison reads the descriptions on demand and reports unreadable sources.

During 0.6.0 development, three fresh reader processes on Rorqual listed the first merged UKB page in 781, 40 and 42 ms. A sampled participant branch with two sessions took 364, 2 and 2 ms. These are host-side directory reads with uncontrolled filesystem cache state. Together with the slower first branch observed during 0.5.0, they point to measuring individual cold branches before introducing persistent SquashFS indexes. Browsing continues to read pages on demand.

## Logical acquisition metadata

Acquisition resource groups use exact sibling entities and preserve original source choices. The inherited-metadata inspector can read SquashFS JSON when all inspected logical ancestors have complete inventories. Paged coverage and conflicting shard sidecars withhold effective values and tree timing summaries. Original member previews remain independently available. This does not index every subject to resolve a single acquisition.
