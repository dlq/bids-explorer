## Message trust boundary

All six clients now reject a message unless `event.origin === window.location.origin` before examining its payload. This uses the current webview origin rather than a hardcoded scheme, host or remote-server name. Existing payload validation, CSP, text-node rendering, bounded previews and host-held source identities remain in place.

Do not require `event.source === window.parent`: a disposable VS Code 1.96.0 webview showed genuine host messages with the expected origin but with `source` equal to neither `window` nor `window.parent`. Such a check rejected real messages. The security regression verifies actual extension-host delivery, then dispatches foreign HTTPS, opaque (`null`) and empty-origin messages against each loaded client; those are ignored while a matching-origin control is processed. It uses standard webview APIs, nonce-restricted test scripts and DOM message events, not private NiiVue or VS Code internals. Test instrumentation is excluded from the VSIX.

Relevant implementation references: [minimum VS Code message delivery](https://github.com/microsoft/vscode/blob/1.96.0/src/vs/workbench/contrib/webview/browser/pre/index.html), [current implementation](https://github.com/microsoft/vscode/blob/main/src/vs/workbench/contrib/webview/browser/pre/index.html), and the [supported webview API](https://code.visualstudio.com/api/extension-guides/webview#passing-messages-from-an-extension-to-a-webview). These references explain the compatibility investigation; production code uses only the standard message event origin.

## Verification and scope

The tar replacement tests cover both indexing and selected-member reads, using a new regular-file inode, directory replacement and symlink replacement between the preliminary stat and open. Every replacement is rejected before a read or selected-payload callback, and every acquired descriptor closes.

Formatting, type checking, linting, all 170 unit tests and the per-file coverage gate passed. Full integration tests passed on VS Code 1.96.0 and 1.145.2: 56 passed on each, with two external public-data fixtures left opt-in. The six sender regressions ran in those suites. Semgrep rule fixtures, its ordinary scan and the full source scan passed. Packaging verified all six origin guards and excluded test probes and unsafe fixtures.

[Hosted CodeQL](https://github.com/dlq/bids-explorer/actions/runs/42415379161) confirmed alerts 1 and 5–10 fixed for source commit `a1cf22a`. [Hosted CI](https://github.com/dlq/bids-explorer/actions/runs/42415379217) passed. Alerts 2 and 4 were dismissed as used in tests, and alert 3 as a false positive, with review comments. GitHub reported zero open CodeQL alerts after these dispositions. No production paths or whole test suites were excluded from analysis.

The checksum-matched security build also passed a synthetic Rorqual Remote SSH smoke test on VS Code 1.145.2: seven NIfTI cases across loose/ZIP/tar/gzip tar/SquashFS, literal JSON previews for all five storage forms, and seven native Image-sidebar cases. The old development-publisher copy was disabled only in the disposable test client to avoid the already-documented duplicate-command collision. No research datasets or source files were modified.

[Structured evidence](evidence/codeql-review-2026-11-07.json) records the dispositions and test scope without machine-specific paths. This review did not publish a Marketplace release. Alert resolution is not proof that every possible vulnerability is absent.
